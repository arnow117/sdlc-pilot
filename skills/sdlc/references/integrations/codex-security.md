# Codex Security — 可选安全扫描适配

Codex Security 是可用于 [`security-scan`](../validate-modes/security-scan.md) 的源码安全分析工具。CLI/SDK 默认使用
Codex 运行时与配置的模型；宿主也可能提供插件能力。它不是 SDLC 的生命周期状态、通用依赖扫描器或免费规则引擎。
本适配不安装工具、不选择凭据、不自动调用模型；实际执行必须满足当前授权和阶段协议。

## 按需检查执行机器

当当前阶段实际需要使用 Codex Security 时（通常在 validate），在实际运行扫描的机器上检查；实际执行转到另一台机器或
环境发生变化时重查。同一会话中的有效结果传入阶段 brief，不保存安装状态或凭据到 `.sdlc-v1/**`。普通 SDLC 工作、
仅评估扫描适用性或选择其他扫描工具时，不要求检查 Codex Security，也不因此提示安装。

1. 在当前已加载的 `sdlc` skill 目录中执行已随该 skill 分发的只读探针：

   ```sh
   python3 scripts/check_security_dependency.py
   ```

   它只发现 PATH 中的长命令、可能重名的 `cs` 及 Node/npm 候选，不运行这些命令，不连接网络，不读取凭据。
   返回 `plugin`、`version`、`authentication` 均为 `not_checked`，`scan` 为 `not_run`。进程成功仅表示探针运行，
   不表示扫描器已安装、已配置或扫描通过。Python 不可用时按宿主提供的只读命令发现能力检查；仍未知就如实说明。
2. 通过当前宿主实际可发现的工具/技能清单判断是否有可用的 Codex Security 插件；无该能力时标未知。源码目录、插件文件、
   PATH 入口或 npm/npx 可用均不能单独证明插件可加载、版本兼容或认证有效。只发现 `cs` 时先核实它不是同名工具。
3. 未发现 CLI 且没有已确认可用插件时，向用户说明缺口和安装、配置选项，提供
   [官方安装与认证入口](https://github.com/openai/codex-security#quick-start)。插件状态未知时同时说明未知；
   仅有歧义短命令时先提示核实身份。CLI 候选已发现但版本、认证或运行依赖未知时，说明尚未核实；已确认缺失时指出具体缺项。
   提醒不阻断与安全扫描无关的普通 SDLC 工作；必要扫描不可运行仍按验证归因处理。

不自动运行 `npx`、安装包、拉镜像、登录或连接模型服务来探测能力。上游 CLI 的离线登录状态查询可能导入现有凭据，
因此不把它当作无副作用的启动探针；需要实际扫描时，再按已选 provider、认证方式和现有授权核实其具体行为。
只报告是否可用及原因，不读取、打印、复制或保存凭据值。

## 运行已选扫描

下述流程适用于本机已实际确认可用的 CLI；Codex 插件入口按其当前可加载技能及相同范围、预算和证据要求执行。
该适配基于 Codex Security SDK/CLI 0.10.0 源码；GitHub Action 可能锁定其他版本，不能假定参数和产物完全相同。
当前机器在首次使用前应检查实际版本的帮助及兼容性；未知版本或未核实的产物保持未知。

1. 主 Agent 与验证执行者确认目标 checkout、完整 `H`、实际比较基线 `B`、需要调查的边界和适用排除。差异扫描应先固定实际 merge-base，使用固定的 base/head，而不是运行中会移动的分支名。Codex Security 0.10.0 对 committed-diff 的 checkout 有 clean/full 等要求；不满足时报告，不能自动 stash、清理或提交。允许时使用宿主提供的隔离 checkout。
2. 确认 provider、模型、认证方式、被发送给服务商的源码范围、次数、并发、预算、独立输出目录和取消/收尾方案。原始产物和 scanner 私有状态放在目标仓库及其外围 Git worktree 之外的受控位置，并保留可持续访问的证据引用。请求消耗额度的扫描之前遵守用户及项目已有授权要求。不要假定本会话的模型、登录或订阅额度会被 CLI 继承。
3. 用实际 CLI 的帮助核对 `scan` 及所需选项。优先使用适合当前义务的 Standard 定向路径或固定 diff；`--path` 和 `--diff` 的组合与否、`--head`、`--headless`、`--json`、`--max-cost`、`--max-time` 等以已安装版本为准。完整命令、工作目录、退出码及版本记入既有工程证据。
4. `--max-cost` 是按已记录 Token 计算的估算停止阈值，不保证账单硬上限；在途请求可超额。Standard 的 `--max-time` 是调查提示，不是硬超时。需要硬期限或供应商支出控制时单独配置并验证。不要启用自动 patch、PR、上传、额外扫描后提示或独立验证来绕过既有授权与预算；0.10.0 的 `--validate` 不能与 `--max-cost` 联用。
5. 按已安装版本检查完整状态及原生 manifest、findings、报告、覆盖/排除和实际 usage；保存可访问的原生产物及摘要。0.10.0 的 `scan-manifest.json`、`findings.json` 和 `report.md` 仅是版本化线索，SARIF 可能不可用；缺少必要证据不能写成通过。

原生退出码和 `completed` 只说明对应工具的执行结果，仍须按 `security-scan` 与当前产品策略裁定。dry-run、mock、导入和
空 diff 的短路不是实际安全扫描；中断或预算停止后，保留已观察的发现和未审计范围。review 复用适用结果，发现缺口时
提出定向补验，不因进入 review 默认重烧一次模型额度。
