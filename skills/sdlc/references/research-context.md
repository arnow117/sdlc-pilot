# 调研上下文（可选）

仅当 product-design/spec 需要外部事实，或 plan 需要比较复用方案时按需加载。它不新增阶段、状态、配置或独立调研报告；
复用顺序和最多三个候选仍由 [sdlc-plan](../../sdlc-plan/SKILL.md) 定义。

## 在检索前写清问题

先在当前产品或工程上下文简要写明已确定的决策问题、目标和约束，以及会改变范围或选择的关键未知项。复用已确认事实，
不把搜索结果反推为用户需求；产品阶段只澄清行为、指标、范围和可行性，工程阶段才决定依赖和实现。

## 可选来源与证据

只使用当前项目或用户已配置、且与问题相关的知识库或 Stars 适配；未配置时跳过，查询无匹配记为 `NO_MATCH`，不可用时说明限制。
它们只提供比较输入，不能替代项目代码、现有依赖、官方维护扩展或必要的外部资料检查。不要自动安装、认证、修改配置、
发起付费调用或把来源不可用写成没有候选。

对关键结论保留原始来源、版本或 commit、核查日期和适用条件，并区分实际取得的证据：

| 证据 | 可以说明 | 不能说明 |
|---|---|---|
| 已记录知识 | 历史候选、条件或结果 | 当前版本仍适用 |
| 官方资料 | 维护方声明的能力或限制 | 当前环境已运行 |
| 源码核对 | 指定版本的实现或扩展点 | 已运行通过或满足业务效果 |
| 实际运行 | 已记录环境和输入下的结果 | 未覆盖环境或输入同样成立 |
| 业务验证 | 已记录样本和指标下的验收结果 | 未覆盖任务、规模或版本同样有效 |

把来源主张、观察事实和推断分开；仅做资料或源码核对时，保留适用条件和未验证项，不能称为运行或业务验证。
将产品事实写回产品上下文，将复用候选、证据、决定和未知项写回工程上下文；引用原始来源，不复制检索记录或建立新账本。
