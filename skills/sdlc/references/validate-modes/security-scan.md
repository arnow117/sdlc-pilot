# Validate mode: security-scan

对当前交付的安全义务运行或核实适用的扫描证据。此模式是验证方式；`security` 角色负责安全判断，二者不互相替代。
可使用项目已授权的规则扫描器、现有 CI 产物或 [Codex Security 适配](../integrations/codex-security.md)。工具能力不同：
规则扫描覆盖的模式不自动证明业务授权正确，模型源码审查也不自动覆盖全部依赖或运行环境。

## 选择与输入

认证、授权、租户、支付、密钥、个人数据、原始 SQL、文件系统、外部输入或信任边界变化时，评估并记录所需安全扫描；
依赖、构建、CI 权限和安全检查变化按实际风险与验收决定。纯文案、无安全语义的样式或其他不适用改动可以不选本模式，
说明理由；未选择不表示扫描通过。选中后，不因工具缺失、费用或已有 `security` 角色静默取消必要检查。

在现有工程上下文声明：

- 当前候选 commit `H`、固定的比较基线 `B`（适用时）、受影响边界、必须覆盖的路径/行为与有理由的排除。
- 工具、版本、规则/配置或提示来源、运行环境、证据位置、严重度处置标准及实际授权；模型扫描另列 provider、模型、范围、次数、并发和费用/时间约束。
- 与产品验收关联的安全义务，以及历史发现、当前变更和未解决问题的处置方式。证据或工具不具备所需能力时保留缺口。

工具发现、安装建议和供应商细节按适配说明处理。扫描消耗模型额度、发送源码或访问外部系统时，按实际授权范围运行；
不自动下载、登录、调用模型、修补、上传或发布。已有项目规则和工具可以复用，但不能冒充它们未覆盖的能力。

## 执行与证据

1. 在适用的独立 Validate 中，以已冻结的目标和策略运行选定工具，或按阶段协议核实可复用的等效证据。记录实际命令、退出码、开始结束、执行环境、工具版本、配置/规则与预算；未执行写 `NOT_RUN`。
2. 保留原始报告、相关日志及其可持续访问的路径和 SHA-256；在现有工程上下文关联 `H`、`B`、扫描范围、实际覆盖、排除、未完成项及结果。hash 证明字节一致，不证明结论真实或覆盖完整。
3. 对报告的发现保留原生 finding ID/fingerprint、受影响位置、攻击入口/约束、证据和实际存在的反证或 proof gap。缺失字段写未知，不从行号生成冒充跨版本稳定的身份；不同工具的 ID 不自动等价。
4. 复核本次变更的可达性、影响与适用策略。区分已确认须修问题、历史问题、误报与待调查问题；没有发现或进程退出 0 不证明所有必要范围已检查。
5. 外部模型用量记录可获取的 input/output/cache、估算费用、覆盖状态及实际费用证据或未知项。原生产物中的覆盖、反证或 usage 不存在时保留缺口，不虚构字段。

原生退出码保留原值；不同工具的非零退出可能代表发现、执行错误或其他状态，不能仅凭数字分类。Codex Security 的
`dry-run`、mock、空差异短路或导入已有结果不构成一次真实扫描；完成的产物和必要覆盖也不能由这些动作推断。

## 判定与复用

沿用 [`sdlc-validate` 四分类](../../../sdlc-validate/SKILL.md#验证归因)：

| 事实 | 归因 |
|---|---|
| 实际扫描或适用等效证据完整，覆盖和当前策略均满足 | 与其他必要检查一起判断 `PASS` |
| 已确认本次须修复的漏洞或安全验收阈值不满足 | `IMPLEMENTATION_FAILED` |
| 已确认缺少必要工具、凭据、运行时或服务 | `ENV_BLOCKED`；解决环境后重验，不因此将 Task 自动退回实现 |
| 中断、预算耗尽、原因不明、产物或必需覆盖不足 | `INCONCLUSIVE`；保留缺口并补证据 |

多个问题分别归因；已确认漏洞不能被另一项环境故障覆盖。证据只在相关代码、配置、环境、工具、范围和当前安全义务
仍适用时复用。review 对同一 `H` 的原始证据、发现、覆盖和缺口作独立判断；证据不足时提出定向补验，不默认重跑相同
模型扫描。Build 的扫描不自动代替独立 Validate，旧 commit 或未完成扫描也不自动证明当前候选通过。
