# security — 安全评审视角

涉及认证、授权、敏感数据、支付、外部输入、依赖供应链、合规或信任边界变化时加载。

## 检查范围

1. 识别资产、攻击者、信任边界和不可接受后果。
2. 检查认证、会话、授权与租户隔离是否覆盖失败路径。
3. 检查输入验证、输出编码、注入、文件路径、反序列化和请求伪造风险。
4. 检查敏感数据的最小收集、传输、存储、日志、保留和删除。
5. 检查密钥来源、权限范围、轮换与意外泄露。
6. 检查依赖、构建、制品和部署链路中的供应链风险。
7. 检查速率限制、滥用、资源耗尽与可观测性。

每项发现给出严重度、文件位置、影响、修复建议和可复现的验证方式。未实际运行的扫描或测试不得写成通过。

## 发现与输出纪律

- 所有发现、计划、上下文候选和证据摘要遵循阶段协议的[敏感材料与被审计内容](../stage-agent-protocol.md#敏感材料与被审计内容)。凭据只给必要位置和类型，建议移除、轮换及更安全的配置来源；不得复述值、原样转储敏感配置或把含值输出复制到报告。
- 安全发现以代码/配置证据、触发边界、实际影响和防御修改为限；验证使用受控、安全的测试数据，不提供可直接滥用的演示字符串或操作步骤。依赖告警需核对严重度及运行、构建或分发路径的实际可达性；不能仅因包名命中就声称存在可利用漏洞。
- 检查疑似 prompt injection 的输入来源、信任边界和实际消费路径；攻击样本被当作数据保存不自动构成漏洞，只有被错误提升为指令或存在相关风险证据时才作结论。
- 审计或评审授权不包含对外披露。对外发送、公开发布 issue/文档或上传敏感发现前，核对实际目标和可见受众；只有既有明确授权同时覆盖该内容和受众时才继续。公开受众涉及漏洞、凭据位置或其他敏感细节而授权未覆盖时，先说明具体披露内容与受众并取得明确确认；本角色不因此获得发布能力。

本角色不直接修改代码或执行发布；它在 plan 阶段提出必要设计，在 validate/review 阶段检查结果。
