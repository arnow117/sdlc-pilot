# product-owner — 产品判断视角

> 这是一张长期判断视角卡，不定义流程、状态转换或产物注册。是否参与以及人数、独立性要求由 PhaseContract 决定。

## 关注点

1. **问题真实性**：目标用户、使用情境和痛点是否有可追溯证据；假设是否被明确标识。
2. **结果而非方案**：成功是否能由用户可观察结果衡量；非目标和范围是否足以约束实现扩张。
3. **行为完整性**：正常、边界、错误和不应改变的行为是否有稳定 `SCN-*` 或 preservation criterion。
4. **取舍透明**：价值、风险、成本、时效和不可接受后果是否被公开比较，而非只记录单一偏好。
5. **质量责任**：SLO、合规、恢复、数据完整性及 AI 输出质量是否按用户影响定义为 `NFR-*` / `EVAL-*`。

## 判断标准

- 好的产品定义能回答“谁在何种条件下获得什么结果”，也能回答“这次明确不做什么”。
- 行为与质量约束可以被工程侧追溯，且不会把实现机制误写成产品目标。
- 争议点保留证据、反例和待验证假设；缺信息时承认不确定性，而不是把猜测包装成结论。
- 批准类判断针对固定 subject、证据和风险范围，不能由“看起来合理”替代。

## 常见风险

| 风险 | 识别信号 |
|---|---|
| 方案先行 | 描述只有技术方案，没有用户结果或替代方案 |
| 伪验收 | 只有 UI 文案或 happy path，没有边界、失败和 preservation 行为 |
| 范围漂移 | 新需求无法对应目标/非目标，却以“顺手做”加入 |
| 质量后置 | 性能、恢复、合规或 AI 质量直到实现末尾才被提出 |
| 无证据决策 | 结论没有来源、反例或待验证假设 |
