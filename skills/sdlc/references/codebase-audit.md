# 存量代码审计

为 `sdlc-backlog` 提供有证据的维护需求来源。只读发现、核验和排序，不实现、不另建计划索引或 lifecycle stage。编排、安全与停止规则唯一遵循 [stage-agent-protocol](stage-agent-protocol.md)。

## 入口与边界

- 先明确目标仓库、包/模块或分支、用户目标、允许检查和输出范围。只读审计不安装依赖、格式化、提交、发布或运行会改变被审计工作树的命令。需要执行的检查须已确认无副作用且在授权和资源边界内；否则只读核对并标为 `NOT_RUN` 或未知，不声称通过。
- 优先复用现有 `project.md` 的命令、surface 与已验证长期来源，并对当前相关源码和配置核对。缺少 project 时直接采集本轮必要事实，不为审计初始化生命周期，也不写第二份项目说明。
- 读取适用的项目指令、README、依赖/CI 配置、相关测试及已有 ADR、产品和设计文档；只读存在且相关的内容。区分已确认决定、假设和过期来源；遵循协议的被审计内容信任边界。
- 命令以仓库实际配置和适用证据为准；区分“定义存在”和“实际成功运行”。工具或 skill 建议仅在目标执行环境可用时给出，不为审计引入新工具依赖。
- 快速检查聚焦热点的正确性、安全与测试；常规检查按风险覆盖九类；深入检查先明确包/模块范围再扩展覆盖。每轮说明实际检查与未审计部分；不规定固定 finding 数或子 Agent 并发数，不把未检查项视为无问题。
- 分支审计使用已核实基线到当前候选的 diff 及直接调用者/依赖作为范围；区分本次引入、原有、被本次变化触发或放大的问题。没有分支差异时如实报告，不静默扩大为全仓审计。

## 九类检查

| 类别 | 有证据时检查 |
|---|---|
| 正确性 | 错误吞掉、空值/边界、状态分支、异步取消与资源释放、并发/事务/幂等、类型逃逸后的实际错误。 |
| 安全 | 按 [security](roles/security.md) 检查身份/权限/租户隔离、输入到解释器或文件路径、敏感数据与凭据、生产配置和可达供应链风险。标准代理或平台约定本身不构成漏洞。 |
| 性能 | N+1、重复扫描及复杂度、无界查询/负载、明确重复的昂贵计算、前端或服务端热点、构建/CI 重复工作；不凭猜测宣称索引或缓存缺失。 |
| 测试 | 关键危险 codepath 的空白、平凡断言、过度 mock、flaky、测试层次缺口、runner 未覆盖目标；高变动区域重构前是否需要特征测试。 |
| 工程债与架构 | 已漂移的重复规则、职责/依赖边界、可证实的死代码、当前真实变体下的抽象不足或多余；不以行数、单调用者或个人风格认定问题。 |
| 依赖与迁移 | 已证实的 EOL、移除时间、关键路径弃维护依赖、重复能力、manifest/lock 不一致；说明受影响路径及迁移风险，不把每次小版本落后都列为问题。 |
| DX 与工具 | 实际缺失或失效的开发/检查命令、配置、反馈回路、初始化说明、必要环境说明和错误诊断能力。 |
| 文档 | 有实际使用成本的错误示例、缺失公共契约或无法复原的关键决定；低价值文字补齐不优先。 |
| 方向 | 已声明但未交付的产品意图、成组未完成路径、实际用户摩擦或低成本相邻能力；必须给本仓证据和取舍，不以通用功能清单代替需求。 |

## 发现格式与核验

每条候选用短条目记录：类别；准确 `file:line` 与符号；观察到的行为和触发条件；具体影响；修复工作量 S/M/L（含必要验证）；修复风险及理由；置信度 HIGH/MED/LOW；一至三句修复或调查方向。通常保留最强的二至五个位置，广泛重复时补充有界搜索范围。未运行检查、推断与未知项明确标记。

缺少可用验证基线本身可以是发现。只有风险实际依赖该基线时，才把建立验证或特征测试作为后续维护工作的前置条件，不阻塞无关的最早真实增量。

汇总者在呈现前自行打开每条拟保留发现的引用，核对位置、触发条件与实际影响；子 Agent 摘录和行号只作线索。修正错位证据、合并同根因重复，降低或拒绝不能证实的结论。LOW 置信度只提出调查，不直接要求按猜测修复。

已确认的产品/架构取舍和标准平台行为不直接算缺陷；先检查决定的适用条件及当前实现。实现超出该决定或文档与代码已漂移时，报告具体差异和影响，不用旧决定压掉新证据。

委托有界只读分析时，brief 给出本文件在执行环境中可读的路径、必读章节、仓库范围、跳过范围、实际风险和适用决定；要求确认引用可读并只返回发现，不修复、不转储文件。每份 brief 显式带入协议要求的两条安全限制，不能假设子 Agent 继承。缺资料时报告缺口，不凭目录名或旧报告编造。

## 呈现、选择与回流

1. 缺陷和维护项按具体影响、工作量、置信度及修复风险给出排序理由；必要验证前置、高置信度安全问题和可清楚验证的改动优先。建议优先级沿用现有 P0–P3，不创建自动评分或改写 readyqueue。
2. 方向建议单独列出，说明服务谁、证据、取舍及粗略工作量。被选中后先明确产品结果或调查目标，不自动扩大为实现全部方向。
3. 遵循现有用户选择与授权规则，再把选中结果交给 backlog 捕获；已有明确选择不重复询问。推荐可以是一小组高价值项；无交互或没有答复不产生新的选择授权。未选中项不批量写交付计划。
4. 记录本轮纠正、合并、拒绝或不值得做的项、证据、理由与适用条件。有关联的合法 Requirement 时，写入其产品上下文的来源/处理说明；已进入 Feature 的实现评审意见沿用其工程上下文和 [receiving-feedback](receiving-feedback.md)。没有合法关联上下文时，只在当次输出中记录；不创建审计容器 Requirement、独立拒绝账本或第二进度表。
5. 再次遇到相关发现时，先读可访问的既有 Requirement、当前上下文和相关拒绝理由。只有问题、版本和适用条件仍匹配时才复用拒绝结论；有新证据或决策漂移时重新核验。不存在持久来源时，不声称跨会话已去重。
6. 从旧报告恢复或准备交付前，有界核查选中 finding 是否仍存在、依赖是否已满足。已被独立修复或证据消失时报告事实，按现有状态规则处理，不直接实施过期修复、不自动改写已发布记录。旧完成证据不能证明当前版本仍通过。

完成输出：审计版本和工作区事实、实际范围/检查及未审计部分、核验后的维护发现、独立列出的方向选项、拒绝或合并理由、依赖与待选择项。没有高价值发现可明确说不值得做；不为凑数量制造工作，不将静态推断说成复现或测得收益。
