# 联动验证

三种证据分开记录：状态测试、实际 UI 操作、视觉检查。任何一种都不能代替另两种。

## 状态测试

从已知 fixture 调用 UI 使用的同一套业务 action。选择会造成真实误判的边界，而不是复制实现表达式作为断言：

| 类别 | 需要观察的结果 |
|---|---|
| 成功路径 | 主实体、关联记录、可用数量和汇总同时满足期望 |
| 非法状态/权限 | 整个状态不变，返回可理解的拒绝原因 |
| 重复操作 | 不重复发放、扣减、占用或追加记录 |
| 连续操作 | 提交、拒绝、重试、成功之后状态仍正确 |
| 多对象 | 对象 A 的操作不污染 B；身份切换后按数据范围展示 |
| 配置/历史 | 若有快照语义，旧对象不被新配置重算 |
| 重置/延迟 | 重置后旧定时结果不能覆盖新状态 |

对库存、名额、余额等共享资源，写下领域不变量，并在动作完成后检查。状态校验失败不得发布部分结果。测试失败要核对规则与实现，不应通过放宽断言来绕过矛盾。

## UI 联动

从实际用户入口操作，不直接注入目标状态再截结果图。典型双端路径：

1. 读者端发起动作，记录对象标识和数量。
2. 切到后台，确认同一对象及相关计数。
3. 后台执行处理，再切回读者端。
4. 检查列表、详情、标签、下一步操作和汇总一致。
5. 覆盖一个失败/取消分支，确认没有伪成功或错误副作用。

同时检查查询真的过滤、表单错误能修正、取消能返回、弹窗可关闭。只出现 toast 不算联动证据。若 UI 工具受限，记录实际完成的部分，不把状态测试改称点击测试。

## 各端形态与适配

- 移动 App：在目标手机宽度和至少一种较短高度检查底部导航、最后一项、主操作和安全区域；桌面预览仍保持移动结构。详情返回后检查查询、选择对象和列表位置，弹层不能跑到预览容器之外。
- 响应式 Web：分别检查目标断点下的导航、列数和内容重排；不以缩放文字替代布局。
- 桌面后台：在主要桌面宽度检查侧栏、过滤区、表格与编辑弹层；窄屏按既定支持范围检查菜单展开、局部滚动和操作可达性。

记录的视口应对应各端实际约定。测试“页面未溢出”不能证明其导航形态符合参考，也不能证明未覆盖的移动办公流程可用。

## 交付物一致性

测试应覆盖打包进去的同一份领域源码。若测试模块与单文件 HTML 通过构建合并，检查最终文件确实由当前源码生成，没有独立复制的第二份业务逻辑。

离线交付检查外部脚本、字体、图片和 API 依赖；使用已有许可浏览器在实际入口验证。浏览器拒绝某个目标时，不以换通道等方式绕过限制。

## 记录格式

记录版本或内容 hash、测试命令及结果、UI 实际步骤与观察、视口及截图、未验证项。按相关输入变化补测，测试通过后不为追求次数重复执行。
